# ADR-001: 采用 Fernet (AES-128-CBC) 作为凭证对称加密方案

> **状态**：已接受
> **日期**：2026-05-29
> **决策者**：ITOps Platform 开发团队

---

## 背景

凭证（密码、API Key、Token、SSH Key 等）需要安全存储在数据库中，不得明文存储。凭证表位于 `modules/foundation/db_models/system_configs.py` 的 `SystemCredential` 模型，字段 `credential_value_encrypted` 用于存储加密后的凭证值。

## 决策

采用 `cryptography.fernet.Fernet` 对称加密方案：

- **算法**：Fernet = AES-128-CBC + HMAC-SHA256 + base64
- **密钥长度**：128 位（AES-128）
- **主密钥管理**：通过环境变量 `CREDENTIAL_ENCRYPTION_KEY` 注入；若未设置则从 `~/.itops/credential.key` 文件加载；若文件也不存在则生成随机密钥并存入文件
- **密钥轮换**：通过 `rotate_credential()` 接口支持凭证级轮换

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| Fernet（当前选型）✅ | 零依赖（Pydantic/V2 已有 cryptography）；API 简洁；内置防重放 | AES-128（非 AES-256）；非 AEAD |
| AES-256-GCM | AEAD；256 位密钥 | 需自行处理 IV/nonce；依赖 cryptodome 或 cryptography |
| AWS KMS | 托管；硬件安全模块（HSM）| 需 AWS 账户；离线场景不适用 |
| HashiCorp Vault | 业界标准；完整生命周期管理 | 额外部署；架构复杂度高 |

## 结论

对于私有化部署场景，Fernet 方案在安全性和实现复杂度之间取得最佳平衡。凭证加密字段已就位（`credential_value_encrypted`），加解密服务见 `app/domains/config/service.py` 的 `CredentialService.encrypt_value/decrypt_value`。

## 下一步

如需升级到 AES-256-GCM（ADR 后续迭代），只需替换 `encrypt_value`/`decrypt_value` 实现，接口不变。
